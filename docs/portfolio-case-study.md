# 星河集市客服助手：作品集案例说明

## 一句话介绍

这是一个面向虚构电商店铺的本地客服机器人。它用 n8n 编排请求，用 RAG 从 Markdown 知识库检索依据，再用 Ollama 本地模型生成带来源的中文回答；涉及真实订单、地址、支付、争议退款或未知问题时，自动转人工或拒绝猜测。

## 我解决的问题

普通聊天机器人容易出现两个问题：一是把过时或不存在的政策说得很确定，二是遇到订单和退款等业务操作时假装自己能处理。本项目把“回答问题”和“决定是否转人工”拆开，要求每个知识库回答都能追溯到来源，并为高风险场景设置明确边界。

## 技术方案

| 层 | 实现 | 作用 |
|---|---|---|
| 编排 | n8n | Webhook、输入校验、分支、HTTP 调用和响应格式化 |
| 检索 | Node.js 本地 RAG 服务 | Markdown 分块、Ollama Embedding、余弦相似度和词面重排 |
| 生成 | Ollama + `qwen3:4b` | 基于检索资料生成回答 |
| 向量模型 | Ollama + `qwen3-embedding:0.6b` | 将问题和知识片段转为向量 |
| 数据 | 7 份合成 Markdown | 商品、配送、退货、退款、会员和人工边界 |
| 公开 Demo | 静态 HTML/CSS/JavaScript | 不连接本机服务，不暴露密钥，访客打开即可体验 |

## 关键设计

1. 检索结果带有来源文件、章节、片段 ID、更新时间和相似度。
2. 相似度低于阈值时不生成确定性事实，而是返回未知并建议转人工。
3. 订单状态、地址修改、支付信息、争议退款、账户安全和明确的人工请求走转人工分支。
4. 模型、Embedding 服务和 RAG URL 通过环境变量配置，便于切换模型或云端 API。
5. 所有资料都是虚构内容，仓库不包含真实客户信息、API Key 或本地凭据。

## 验证结果

- 20 条合成评测问题：RAG 检索、未知问题拒答和转人工规则 20/20 通过（100%）。
- n8n 手工冒烟测试：退货政策正常回答并返回 `return-policy.md` 引用；订单查询正确转人工；汽车保险等未覆盖问题正确转人工。
- 仓库自动检查：JavaScript 语法、JSON 工作流、数据规模、秘密扫描和单元测试全部通过。

## 演示路线（约 2 分钟）

1. 展示架构图和两个 n8n 工作流：知识库更新、客服回答。
2. 输入“退货需要满足什么条件？”，展示回答、意图和来源引用。
3. 输入“请帮我查询订单现在到哪里了？”，展示 `handoffRequired: true`。
4. 输入“你们卖汽车保险吗？”，展示知识库未覆盖时不猜测。
5. 打开静态 Demo，说明它不访问本机 Webhook，适合公开作品集展示。

## 已知限制与下一步

- 当前使用 JSON 文件索引，适合小规模作品集资料，不适合生产级并发。
- 没有连接真实订单、支付、物流或工单系统，转人工只是模拟响应。
- Markdown 解析较简单，后续可加入 PDF/OCR、增量索引、重排序模型和持久化向量数据库。
- 后续可以增加真实客服渠道适配层，但保持统一的请求/响应契约不变。
